## Mandatory integration completed

The manual pilot Python API and CLI now require a reviewed `--mcp-source-map`
and a separate `--allow-readonly-builtin-tools` acknowledgement. The latter
does NOT prove built-in tools absent, and should only be used when the owner
explicitly accepts the local read-only hobby context. The actual code now
runs `verify_mcp_disabled` before account discovery, passes the exact same
leaf overrides to BOTH account-discovery and first-turn app servers, then
uses `mcpServerStatus/list` and `app/installed` on the actual pilot
app-server BEFORE emitting any `thread/start`. Unknown/active tools fail
closed without a turn, and create an ambiguous/pre-turn diagnostic receipt
without auto retries. Old unguarded CLI use is removed.

The current parser is intentionally strict. If the installed alpha reports
different MCP status fields, Codex must validate its schema and update the
parser plus negative fixtures. This must never be replaced by a bypass flag.

## 2026-10-24 Windows schema and preflight correction

Local validation against the version-matched schema generated by Codex CLI
`0.163.0-alpha.11.2` found that `McpServerStatus` has no `enabled` property and
represents `tools` as an object keyed by tool name, not an array. It also
defines `runtimeStatus` as an optional enum and requires `name`, `authStatus`,
`resources`, `resourceTemplates`, and `tools`. The runtime validator now checks
that schema, requires empty tool/resource catalogs, and rejects active,
unknown, or failed discovery states. Disabled state is established by the
process-scoped config preflight, not inferred from a nonexistent status flag.

The config preflight now adds `-c features.apps=false` and verifies the
effective `apps` row with `codex features list`, in addition to proving all
reviewed configured MCP entries disabled through `codex mcp list --json`.
This matters because Apps/connectors are independent of those configured MCP
entries. On the local CLI, without the override, `app/installed` returned 16
apps with `enabled=true` and `callable=true`; with the process-only override,
all 16 reported both fields false. The guarded status response then contained
seven rows, no tool catalog entries, and no active runtime states.

The order is now mandatory: verify effective CLI config before process launch,
query `app/installed` and reject any enabled or callable app, then query
`mcpServerStatus/list`. Codex's App Server implementation performs temporary
MCP status discovery by collecting tool catalogs, so that request must not be
used as the first disablement check. No settings file is modified by this
process-scoped override. The local account/model doctor completed without
starting a thread or turn; this does not authorize the manual live pilot.
