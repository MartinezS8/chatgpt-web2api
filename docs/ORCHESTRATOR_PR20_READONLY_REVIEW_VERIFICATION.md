# PR-20 — Read-only GitHub reviewer verification (no task finalization)

Date: 2026-10-19. Base: **PR #21**, `codex/orchestrator-v19-ci-event-required-jobs` (`77e03c2390077882dc225fa7d49129636b0d8073`). The new branch is additive and remains Draft. **The original Octo-Lex `master` branch is not changed.**

## Why

The PR #19–#21 work checks PR/CI identity and successful jobs, but a successful workflow is not approval from an independent reviewer. The older mock `ReviewLedger` is deliberately not an authenticated GitHub review. `Store.finalize_verified()` has already been default-denied by PR #15. We must not re-enable it merely because a GitHub GET returned `200`.

## Official GitHub resources and data used

- `GET /repos/{owner}/{repo}` — trusted numeric repository identity.
- `GET /repos/{owner}/{repo}/pulls/{pr_number}` — current HEAD SHA, author numeric ID, base repository ID, open/unmerged/non-draft state. Read before and after reviews.
- `GET /repos/{owner}/{repo}/pulls/{pr_number}/reviews?per_page=100&page=1` — current review history (`state`, `commit_id`, `user.id`, `user.login`, `submitted_at`). GitHub returns reviews chronologically. A complete 100-entry page is conservatively rejected as possibly incomplete; do not allow first-page truncation to hide newer changes requests or dismissals.
- `GET /repos/{owner}/{repo}/collaborators/{login}/permission` — independently retrieved reviewer write/admin permission and returned immutable user ID.

Sources: [GitHub review API](https://docs.github.com/en/rest/pulls/reviews), [GitHub repository permission API](https://docs.github.com/en/rest/collaborators/collaborators).

All HTTP operations in the new adapter are `GET` on exactly these endpoint shapes; redirects, unapproved paths, invalid data, and unbounded responses fail closed. Credentials are provided by a trusted runtime, not supplied by an implementing agent or persisted in review receipts.

## Implemented

`src/chatgpt_web2api/orchestrator/github_readonly_reviews.py` introduces:

1. **`GitHubReviewsHTTP`**: dedicated bounded, no-redirect reader. It does not change GitHub state.
2. **`GitHubReadOnlyReviews`**: validates an operator-configured repository ID and `frozenset` of trusted **numeric GitHub reviewer IDs**. It will not accept a reviewer list generated by an agent's text. The trusted implementation-worker GitHub ID is provided separately by controller configuration.
3. The PR must be open, unmerged and no longer a draft. The current head SHA must match the task's expected SHA. Review author must not be the PR creator or the implementation worker.
4. Review **`APPROVED`** must target exactly that SHA. Superseding `DISMISSED` or unresolved `CHANGES_REQUESTED` removes approval. Unknown states and malformed/out-of-order review history fail closed. Comments and pending reviews cannot grant approval.
5. The latest actual independent repository permission must be `write` or `admin` for the same numeric actor ID. Read/triage/no access is never sufficient.
6. Reviewer threshold is operator configured. The reader verifies that each accepted approval corresponds to a distinct GitHub identity.
7. Re-read the PR after all review/permission queries and reject a changed HEAD.
8. Return a frozen `ReviewObservation` containing only IDs, SHA, timestamp and `assurance=provider_read_only_review_unfinalized`. Both `production_finalization_permitted` and `live_send_permitted` are **always false**.

## Evidence and limits

- Local Linux / Python 3.13 **53 new isolated tests passed**.
- Combined staged regression run containing exact-GitHub-blob versions of `store.py`, PR #21 `github_readonly_evidence.py` and PR #20 `provider_evidence.py`: **174 tests passed + 8 subtests**.
- This stage tests no live GitHub permission/review event with a real, approved reviewer. Through the connected GitHub tool, PR #21 had **zero review submissions** at inspection.
- `ruff` is not installed locally. The complete cumulative repository suite, upstream tests, Windows/Python 3.11 and 3.12 CI, and real HTTP credentials smoke test remain pending; **do not merge this Draft** based on the staged tests alone.
- A double PR-HEAD read only minimizes, not eliminates, races: review state can change immediately afterwards. The finalizer must revalidate at its own decision boundary. A GitHub review does **not** constitute required user consent for external writes.
- This new review adapter is intentionally **not yet wired to a task-bound persistent `ProviderEvidenceLedger`**. That linkage needs to bind canonical repository ID, task ID, attempt, sealed package, current PR head and verified reviewer identity under an atomic fencing transaction; don't permit independent submissions or user-provided reviewer strings to bypass it.
- This module does not grant live worker sessions, file uploads, callbacks, model/High selection, ChatGPT Plus app selection, or provider write access.
