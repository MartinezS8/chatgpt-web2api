# PR-18: Task-bound provider evidence (read-only, fail-closed)

**Repository:** `MartinezS8/chatgpt-web2api`  
**Parent:** Draft PR #19, `codex/orchestrator-v17-github-readonly-evidence`  
**Scope:** Add a conservative SQLite audit record for GitHub PR/CI observations. No new external write or ChatGPT browser action.

## Review finding

The previously introduced `GitHubReadOnlyEvidence.inspect()` returns an in-memory immutable `ReadOnlyPRRunReceipt` for a repository, open PR head and allowlisted green workflow. It does **not** bind that observation to a durable task, the exact remote turn, the task's sealed attachment/prompt package, or the active write lock. `EvidenceLedger.inspect_mock()` is intentionally mock-only and must **not** be silently promoted to production evidence.

The new `provider_evidence.py` adds **only an audit bridge**, separate from the mock reviewer ledger. It does not mark a task verified/finished, permit a send, authorize a GitHub merge, issue a remote callback, or release a write resource.

## Contract: `ProviderEvidenceLedger.inspect_and_record(...)`

1. **Local identity preflight (before remote GET):** task must exist, be an `implement` task with an occupied slot and `result_received` state. Its write scopes must contain the canonical `github:repo/<numeric_id>` lock or a descendant; arbitrary aliases and a different repository are rejected.
2. **Dispatch identity:** match the *specific* `orchestrator_dispatch_attempts.attempt_id`, `task_id`, status `completed`, current task claim-token hash and exact result reference. Require the corresponding sealed `orchestrator_task_packages.package_sha256` to equal the outbox attempt package SHA.
3. **Provider read:** call the configured `GitHubReadOnlyEvidence.inspect` (repo ID/PR head/allowlisted successful workflow) **without holding a SQLite write transaction**. Check observation age and ensure provider receipt has only `provider_read_only_unreviewed` assurance and **zero action permissions**.
4. **Atomic race check:** in a single `BEGIN IMMEDIATE`, reload all the task/outbox/package fields and require identical claim version, package SHA and result identity. If anything changed while GitHub was queried, abort without sealing evidence.
5. **Immutable audit record:** one provider observation per task, with a digest over task ID, attempt ID, repository ID, PR head SHA, CI run and attempt, package SHA, hash of result reference, and task claim version. A repeated identical check is idempotent; a different run, SHA or task identity cannot replace prior evidence. Store no raw claim token, prompt, attachment body or result reference.
6. **Independent operation:** task remains `result_received`, slot and global resource locks remain held. Local mock review approval, `Store.finalize_verified` and the old direct Controller send remain fail-closed.

## Critical boundaries and remaining findings

- A successful CI run with the same commit SHA does **not** prove who submitted the work, that a reviewer is independent, that a human approved it, or that all required checks/permissions were satisfied. It is a read-only observation, not a release authorization.
- The existing GitHub adapter does not yet enforce the workflow's trigger event (e.g., `pull_request`) or required check/job policy. Its workflow ID allowlist must be configured by a trusted operator, not generated by an agent. Add a strict trigger/job policy before any real release gate.
- A remote PR head may change immediately *after* the double-read and before a later external merge. The future finalizer must re-check current SHA and required status at its actual decision boundary, with separate user consent for consequential actions.
- There is no provider-authenticated callback ingress or independent reviewer approval; these remain separate gates. The current callback/evidence review modules use **mock only** evidence.
- The local receipt is only as trustworthy as the selected reader/configuration: dependency-injected fake readers are for tests. A model-controlled object must never be treated as provider authentication.
- No live ChatGPT transport, Plus app/plugin selection, real attachment upload, GPT-6 High attestations, automatic workflows or merges.
